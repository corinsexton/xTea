## What shipped this session (case/control CC.0 → CC.2, all gated; CC.3 in flight)

**CC.0 — `--tumor`/`--purity` plumbing.** Added `--tumor`/`--purity` to `run_xtea.py`'s CLI, threaded
into `build_type_steps` exactly per master's real executed `run_xTEA_pipeline.sh` (`--purity <p>
--tumor` on clip/disc/cns_filter/transduction/sibling, `--tumor` alone on both postF steps) — no engine
code changes needed, the vendored `x_TEA_main.py` already has both flags end-to-end. **Important
correction to the previous session's plan doc** (written before `x_TEI_locator.py`/`x_post_filter.py`
were read line-by-line): `--tumor --purity 1.0` does **NOT** reproduce a purity-less run byte-for-byte,
and the chr1 gate correctly shows that (31 calls baseline vs 35 with `--tumor --purity 1.0`) — this is
expected, not a bug. `b_tumor` switches the disc-site and postF retention *formulas themselves*,
independent of purity value (`x_TEI_locator.py` line ~458: tumor mode keeps a site when
`(n_left+n_right) >= cutoff` vs germline's `(n_left>half_cutoff AND n_right>half_cutoff) OR
n_left>cutoff OR n_right>cutoff`; `x_post_filter.py` has several more `b_tumor`-gated cutoff/one-side
branches). The purity-*scaling* component specifically was confirmed a true no-op at purity=1.0 (both
runs' logs show identical `Ave coverage is 33.471: ... (3, 5, 1)` automatic-cutoff derivation) —
isolating that from `--tumor`'s separate, expected formula-switching effect. CC.0 gate = argv-shape
match against master's real script (exact diff, not just source reading) + both runs complete without
crashing + purity-scaling isolated and confirmed correct. All three hold.

**CC.1 — case-control filtering steps.** Added `--case-control`/`--normal-bam` to `run_xtea.py`;
extended `build_type_steps` with two new per-type steps mirroring master's `x_somatic_calling.
CaseControlMode` exactly (argv confirmed against the same real executed script): `case_control` filters
the RAW `postF_all` list against the control BAM (`x_TEA_main.py --case_control`), `case_control_hc`
intersects that with the type's own `postF_hc` list (`--case_control --somatic_hc`) for the final
high-confident somatic set. New `cc_hc_path()` helper mirrors `hc_pf_path()`. `run_type_downstream`
returns the `case_control_hc` path instead of `hc_pf` when `--case-control` is on (new `stop_after=
"case_control_hc"`, picked via `type_stop_after = "case_control_hc" if opt.case_control else
"postF_hc"` at all 3 call sites in `main()`). Also found (reading the real script closely): master's
somatic path skips `--gntp_classify` entirely — gene output feeds `--gVCF` directly, confirmed by the
real reference VCF showing `GT=./.` for every somatic call (`x_gvcf.py` defaults to `"./."` when the
genotype column is absent) — made this conditional in `build_shared_tail_steps` too, not a new code
path, just an existing graceful default. **Gate: chr1, control=tumor BAM — ALL 3 types' `postF_all`
candidates (Alu 39, L1 4, SVA 6) collapsed to 0 after case-control filtering, final merged VCF = 0
calls.** Full collapse, not just "near-zero" as the plan allowed for. (The gate script's own SLURM
status showed FAILED — cosmetic only: its trailing `grep -v '^#' "$mvcf" | head -20` report line exits
1 on an empty VCF, and `set -euo pipefail` treats that as fatal *after* the real run had already
finished and printed everything needed — same class of harmless bug as the move-A.2 WGS timing script
fix from the prior session. Fixed in the CC.3 scripts' reporting sections.)

**CC.2 — wire into shared tail.** Turned out to already be complete as a side effect of CC.1: `run_
