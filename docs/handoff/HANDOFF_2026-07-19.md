## What shipped this session (both committed + validated)
1. **Deadlock fix (`a4b0fd3`, realign.hpp).** `realign_one_file` made its bwa stdout `pipe()` without
   `FD_CLOEXEC`; the 3 families realign concurrently via `std::async`, so one family's `fork()` snapshotted
   another's pipe fds pre-exec and carried a sibling bwa's stdout WRITE end across `execlp` → reader never
   saw EOF → circular deadlock (all procs `futex_do_wait`). Fix = a `bwa_spawn_mutex()` serializing
   pipe()+FD_CLOEXEC(both ends)+fork() in `realign_one_file` AND `run_bwa_sam` (dup2 targets stay
   non-CLOEXEC so each child's own stdout/stderr survive exec). Diagnosed live via `/proc/<pid>/fd`
   (a bwa held fd9-WRITE on a sibling's stdout pipe).
2. **Thread-budget fix (`c538420`, scan_adapter.py).** `run_scan_realign` passed `--threads` (tiling) but
   never `--bwa-threads`, so xtea-scan used its default `bwa_threads=4` → `[2,1,1]` across L1/Alu/SVA
   (`bwa mem -t 1` live). The `-n 24` budget never reached the realign → ~4 cores. Fix = new `bwa_threads`
   param (defaults to `threads`, since realign runs AFTER the tiling scan) → emits `--bwa-threads`; the
   run_xtea call site (threads=opt.cores=24) now yields `[8,8,8]`. Python-only, no rebuild.
